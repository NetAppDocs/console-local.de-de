Während der manuellen Installation kontaktierte Endpunkte:: Wenn Sie den Console-Agenten manuell auf Ihrem eigenen Linux-Host installieren, benötigt das Installationsprogramm für den Console-Agenten während des Installationsvorgangs Zugriff auf die folgenden URLs:


[cols="2*"]
|===
| Endpunkte | Zweck 


| \https://mysupport.netapp.com |  


| \https://signin.b2c.netapp.com | (Dieser Endpunkt ist die CNAME-URL für https://mysupport.netapp.com) 


| \https://cloudmanager.cloud.netapp.com/tenancy |  


| \https://stream.cloudmanager.cloud.netapp.com |  


| \https://production-artifacts.cloudmanager.cloud.netapp.com |  


 a| 
* Option 1 (empfohlen):
+
** \https://bluexpinfraprod.eastus2.data.azurecr.io
** \https://bluexpinfraprod.azurecr.io


* Option 2:
+
** https://*.blob.core.windows.net
** \https://cloudmanagerinfraprod.azurecr.io



 a| 
Zum Abrufen von Images benötigt das Installationsprogramm Zugriff auf einen dieser beiden Endpunktsätze. ^1^ Die in Option 1 aufgeführten Endpunkte werden empfohlen, da sie sicherer sind. Es wird empfohlen, die Firewall so zu konfigurieren, dass die in Option 1 aufgeführten Endpunkte zugelassen und die in Option 2 aufgeführten Endpunkte nicht zugelassen werden. Folgendes ist zu diesen Endpunkten zu beachten:

* Die in Option 1 aufgeführten Endpunkte werden ab der Version 3.9.47 des Console Agent unterstützt. Es besteht keine Abwärtskompatibilität mit früheren Versionen des Console Agent.
* Der Console-Agent kontaktiert zuerst die in Option 2 aufgeführten Endpunkte. Wenn diese Endpunkte nicht erreichbar sind, kontaktiert der Console-Agent automatisch die in Option 1 aufgeführten Endpunkte.
* Die Endpunkte in Option 1 werden nicht unterstützt, wenn der Konsolenagent mit NetApp Backup and Recovery oder NetApp Ransomware Resilience verwendet wird. In diesem Fall ist es möglich, die in Option 1 aufgeführten Endpunkte zu verweigern und gleichzeitig die in Option 2 aufgeführten Endpunkte zuzulassen.
